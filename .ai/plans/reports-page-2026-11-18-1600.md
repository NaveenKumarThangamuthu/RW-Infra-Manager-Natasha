## Analysis

Checked against the code on 2026-11-18.

### Storage: `data/reports/` behind a route handler, not `public/reports/`

The brief proposed `public/reports/` plus a `"/reports/:path*"` matcher entry. That works (a `/reports` page and
static files under `/reports/...` coexist in Next 14, and `:path*` matches zero segments too), but it has two
drawbacks, so this plan uses a session-checked route handler reading from a non-public directory instead:

1. **`next start` only serves the `public/` files that existed when the server started.**
   `node_modules/next/dist/server/lib/router-utils/filesystem.js` lines 144-156 read the public folder once into
   `publicFolderItems` when `!opts.dev`. A report dropped into `public/reports/` later would 404 until
   `natasha-dashboard.service` is restarted. A handler that reads the directory per request shows new reports
   straight away.
2. **`public/` is open by default.** The main matcher skips every path with a dot, so the only thing protecting a
   confidential PDF there would be one extra matcher line. Outside `public/`, the file cannot be served at all
   except through the handler, which checks the session itself.

Cost: one extra route file of about 50 lines. `data/` already exists at the repo root (empty, not tracked).

### Auth

- `/reports`, `/api/reports` and `/api/reports/file` contain no dot in the pathname, so the existing main matcher
  in `middleware.ts` already requires a session for all three. The file name travels in the query string
  (`?name=`), which the matcher does not look at. That is why the handler takes a query parameter rather than a
  `/api/reports/file/<name>.pdf` path segment (a dot in the path would skip the middleware).
- Both handlers also call `getServerSession(authOptions)` and return 401 without a session, the same way
  `app/api/settings/theme/route.ts` does, so they stay protected even if the matcher changes.
- `/vulnerability-report.html` and `/vulnerability-report.pdf` stay in `public/` and are already covered by the
  `"/vulnerability-report(.*)"` matcher entry (verified: logged-out request returns 307 to `/login`).

### Iframes

- `next.config.js` sets no headers. A live response from `localhost:3000` carries no `X-Frame-Options` and no
  `Content-Security-Policy`. Nothing in the repo sets either. Same-origin iframes are therefore not blocked.
- The file handler adds `Content-Security-Policy: frame-ancestors 'self'` to its own responses so the reports
  cannot be framed by another site. If a later change adds `X-Frame-Options: DENY` globally (app or Cloudflare),
  switch it to `SAMEORIGIN` for `/api/reports/file` and `/vulnerability-report*`.
- Mobile browsers (Android Chrome in particular) do not render PDFs inside an iframe. The viewer always shows
  "Open in new tab" and "Download" buttons, and a short hint under the PDF frame on small screens.

### The CSV

16 lines, LF line ends, no BOM, every row has 4 fields, no newlines inside fields. Header:
`"digest_text","count_star","sum_rows_examined","sec"`. `digest_text` is up to 1,116 characters and contains
commas and backticks. The largest number is about 3.5e12, which is safe as a JS number. The parser is still
written generically (step 6) so later CSVs work.

### 2. `lib/reports.ts` (server only)

```ts
export type ReportKind = "pdf" | "csv" | "html";
export interface ReportEntry {
  id: string;            // file name, or "vulnerability-report" for the fixed entry
  title: string;
  kind: ReportKind;
  sizeBytes: number;
  modifiedAt: string;    // ISO
  viewUrl: string;       // server-built, same origin
  downloadUrl: string;
  downloadName: string;
  alt?: { label: string; url: string };
}
```

- `REPORTS_DIR = path.join(process.cwd(), "data", "reports")`.
- `KIND_BY_EXT: Record<string, ReportKind> = { ".pdf": "pdf", ".csv": "csv", ".html": "html", ".htm": "html" }`.
  Files with any other extension are not listed and not served (so there is no "other" kind).
- `CONTENT_TYPE: Record<ReportKind, string>` = `application/pdf`, `text/csv; charset=utf-8`,
  `text/html; charset=utf-8`.
- `SAFE_NAME = /^[A-Za-z0-9][A-Za-z0-9._ -]{0,199}$/`.
- `TITLES: Record<string, string>`:
  - `"RCA-ES-2026-11-11-Elasticsearch-CPU.pdf"` → `"RCA: Elasticsearch CPU, 11 Nov 2026"`
  - `"events_statements_summary_by_digest_202611041158.csv"` → `"MySQL statement digests, 4 Nov 2026"`
- `titleFromName(name)`: use `TITLES[name]` if present; otherwise strip the extension and replace `_` and `-`
  with spaces, but keep `YYYY-MM-DD` dates intact (replace dashes that are not between two digits, then
  underscores), collapse repeated spaces, trim.
- `listReportFiles(): Promise<Array<{ name: string; kind: ReportKind; sizeBytes: number; modifiedAt: Date }>>`:
  `fs.promises.readdir(REPORTS_DIR, { withFileTypes: true })`; keep entries where `isFile()` is true (this drops
  directories and symlinks), the name matches `SAFE_NAME`, and the lower-cased extension is in `KIND_BY_EXT`;
  `stat` each. If the directory does not exist (`ENOENT`), return `[]`.
- `findReportFile(name: string)`: return the entry from `listReportFiles()` whose `name === name`, else `null`.
  The path that is opened is always `path.join(REPORTS_DIR, entry.name)` where `entry.name` came from `readdir`.
  The client-supplied string is only ever compared, never joined into a path.
- `vulnerabilityReport(): Promise<ReportEntry | null>`: `stat` `public/vulnerability-report.html` under
  `process.cwd()`; if missing return `null`. Otherwise `{ id: "vulnerability-report", title: "Vulnerability
  report", kind: "html", sizeBytes, modifiedAt, viewUrl: "/vulnerability-report.html", downloadUrl:
  "/vulnerability-report.html", downloadName: "vulnerability-report.html" }`, plus
  `alt: { label: "PDF version", url: "/vulnerability-report.pdf" }` when `public/vulnerability-report.pdf` exists.
- `listReports(): Promise<ReportEntry[]>`: map files to entries with
  `viewUrl = "/api/reports/file?name=" + encodeURIComponent(name)`, `downloadUrl = viewUrl + "&download=1"`,
  `downloadName = name`; append the vulnerability entry if present; sort by `modifiedAt` descending.

Keep each function to a single return where practical and under 30 lines.

### 6. `components/screens/reports/csv.ts` (pure functions, no React)

`parseCsv(text: string): string[][]` — a single-pass state machine:
- Remove a leading BOM (`\uFEFF`).
- Field separator is `,`. Quote character is `"`.
- A field that starts with `"` is quoted: commas and line breaks inside it are data; `""` inside it is one
  literal `"`; the closing `"` ends the quoted part. Characters after the closing quote up to the next separator
  are appended as-is.
- Unquoted fields are taken literally (no trimming).
- Row ends are `\r\n`, `\n` or `\r` outside quotes.
- A final line break does not create an extra row; rows that are completely empty (one empty field) are dropped.
- An unterminated quote at end of input closes the field and the row (no throw).

`analyse(rows: string[][]): { header: string[]; body: string[][]; numeric: boolean[]; long: boolean[] }`:
- `header = rows[0]`; `body = rows.slice(1)`, each row padded with `""` or cut to `header.length`.
- `numeric[i]`: at least one non-empty cell, and every non-empty cell matches
  `/^-?\d+(\.\d+)?([eE][+-]?\d+)?$/`.
- `long[i]`: not numeric and the longest cell is over 60 characters.

`formatNumber(raw: string): string`: `Number(raw)`; not finite → return `raw`; integer →
`toLocaleString("en-US")`; otherwise `toLocaleString("en-US", { maximumFractionDigits: 2 })`. Empty string → `"—"`.
